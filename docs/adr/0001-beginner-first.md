# ADR-0001: 面向小白用户优先而不是面向熟练开发者优先

**Date**: 2026-03-30
**Status**: accepted
**Deciders**: 项目维护者

## Context

原有文档结构默认读者具备基础 API 调用能力，页面内容偏概括，术语解释不足，工具页详略严重不均。实际目标用户已经明确转向“没读过文档、网络概念也不熟悉的 Windows 小白用户”，原有写法不再匹配。

## Decision

全站信息架构、首页表达、教程颗粒度和排障方式统一改为新手优先。文档的第一目标是帮助用户从零跑通，而不是优先服务熟练开发者的快速参考阅读。

## Alternatives Considered

### Alternative 1: 继续维持开发者参考站定位
- **Pros**: 页面更短，维护成本更低。
- **Cons**: 目标用户读不懂，首轮成功率低。
- **Why not**: 与当前项目目标用户直接冲突。

### Alternative 2: 同时兼顾熟手和新手，但不重构结构
- **Pros**: 看起来覆盖面更广。
- **Cons**: 首页和工具页会继续两头不到岸。
- **Why not**: 不解决当前最核心的理解门槛问题。

## Consequences

### Positive
- 文档路径更清楚，更适合第一次配置的用户。
- 后续所有新页面都有统一的受众基准。

### Negative
- 页面长度会增加。
- 熟手用户需要多点几次才能直达具体字段。

### Risks
- 如果维护时重新回到“熟手优先”，文档会再次失去一致性。通过 ADR 和统一模板约束来降低这个风险。
