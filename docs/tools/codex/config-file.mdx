## 官方依据

<GlossaryHint title="Codex 官方配置字段">
  Codex 官方配置参考说明：配置文件为 `config.toml`，可以通过顶层 `model` 设置模型，通过顶层 `model_provider` 选择 provider，并在 `model_providers` 表里配置自定义 provider 的 `name`、`base_url`、`env_key` 等字段。参考：[OpenAI Codex config reference](https://developers.openai.com/codex/config-reference)。
</GlossaryHint>

<StepChecklist title="步骤 3：写入 ForOpenCode provider" items={[
  '顶层 `model` 写 `gpt-5.4`。',
  '顶层 `model_provider` 写 `foropencode`。',
  '在 `[model_providers.foropencode]` 下写入名称、Base URL 和 env_key。',
  '确认 `env_key` 和你设置的环境变量名完全一致。',
]} />

<GlossaryHint title="Codex 里最容易写错的三个地方">
  一是把路径写错，二是把环境变量名写错，三是把 Base URL 漏掉 `/v1`。这三项只要有一项不一致，Codex 就会像没配好一样报错。
</GlossaryHint>

```toml
model = "gpt-5.4"
model_provider = "foropencode"

[model_providers.foropencode]
name = "ForOpenCode"
base_url = "https://www.foropencode.com/v1"
env_key = "FOROPENCODE_API_KEY"
```

## 成功和失败判断

<SuccessCard title="成功判定">
  <ul>
    <li>新会话可以正常回复。</li>
    <li>不再出现找不到 Key、401、地址不可达等错误。</li>
    <li>需要回退时，恢复 `config.toml.bak` 并重启即可。</li>
  </ul>
</SuccessCard>

<ErrorCard title="常见失败点">
  <ul>
    <li>`FOROPENCODE_API_KEY` 没设置，或环境变量名和 `env_key` 不一致。</li>
    <li>`base_url` 少了 `/v1`。</li>
    <li>TOML 表名写错，例如把 `[model_providers.foropencode]` 写成了别的名字。</li>
    <li>改完配置后没有重启终端或 VS Code。</li>
    <li>当前 Codex 版本对第三方 provider 的支持行为变化；无法确认时请先回到 CC Switch 配置方式。</li>
  </ul>
</ErrorCard>

<WindowsTip title="不确定就不要硬改">
  如果你看不懂 TOML 或不知道配置文件在哪，直接使用 [Codex：CC Switch 配置](/tools/codex/ccswitch) 更安全。
</WindowsTip>
