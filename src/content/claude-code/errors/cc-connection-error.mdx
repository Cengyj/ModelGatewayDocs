---

## 问题现象

发送请求后，终端返回：

```text
API Error (Connection error.)
```

该提示只说明当前请求未成功建立连接，不能仅凭这一行判断失败发生在 TCP、TLS、代理还是目标服务端。

---

## 根因分析

可能原因包括：

- 当前 Wi-Fi / 有线网络到服务器路由异常
- 已获授权的代理配置与当前 shell 不一致
- DNS、证书、系统时间或企业防火墙策略异常
- 目标网关或 Anthropic 服务暂时不可用

---

## 修复步骤

**第一步：检查网络到服务器的连通性**

先确认 `/status` 中显示的 Base URL 是预期域名，且不要显示或复制完整 Key。然后对**实际目标域名**做不携带鉴权信息的 DNS/TLS 检查；例如本站所述第三方网关：

```bash
curl -I --max-time 10 https://foropencode.com
```

HTTP 401/403 仍可说明 DNS 和 TLS 已建立；超时、证书错误或域名不符则应先停止发送带 Key 的请求并核对网络与来源。`ping` 被禁并不等于 HTTPS 不通。

**第二步：切换网络环境**

按以下顺序逐一尝试：

1. 核对系统时间、DNS 和目标域名证书
2. 在组织允许的范围内切换到可信网络
3. 如果使用企业代理，按管理员或官方文档配置；不要关闭 TLS 校验或安全软件

**第三步：运行官方诊断**

在终端执行只读诊断 `claude doctor`，会话内使用 `/status` 查看活动配置来源。代理是否生效取决于操作系统、shell、Claude Code 版本和组织策略，本站不再把“TUN/全局代理”写成通用要求。

**第四步：重新启动 Claude Code**

网络恢复后重新执行：

```bash
claude
```

---

## 预防措施

| 做法 | 避免的问题 |
| --- | --- |
| 先核对最终域名、证书和 `/status` | 避免把 Key 发往意外端点 |
| 使用组织批准的网络与代理配置 | 避免为排障关闭安全控制 |
