# CM-002：claude-mem Worker 无响应

<Callout type="warning" title="先确认第三方插件身份">
  claude-mem 是 `thedotmack/claude-mem` 发布的社区插件，不是 Anthropic 官方组件。只从其官方 GitHub 或文档更新；操作前备份 `~/.claude-mem/`。
</Callout>

---

## 问题现象

- 安装 claude-mem 后，Claude Code 工具调用明显变慢或长时间无返回
- claude-mem 的 viewer 或 health 检查无响应
- `npm run worker:status`、日志或端口信息显示 worker 未正确启动

这些现象只能说明插件 worker 需要诊断；不能仅凭端口监听状态断言“进程假活”。worker 端口也不是所有机器都固定为 `37777`。

---

## 本次核对结论

claude-mem `v13.12.4` Release 修复了一类 Windows 下 server handle 状态导致 shutdown 清理被跳过、端口持续占用的问题，并补充了 stale-worker 修复。旧页面针对 v5.x/v10.5.2 的强制杀进程流程不应继续作为当前默认方案。

---

## 安全处理步骤

**1. 核对来源和版本**

前往 [claude-mem 官方 Releases](https://github.com/thedotmack/claude-mem/releases/latest) 核对当前版本、发布日期和更新说明。不要从同名仓库、网盘或镜像下载。

**2. 在官方插件目录运行诊断**

```bash
cd ~/.claude/plugins/marketplaces/thedotmack
npm run worker:status
npm run worker:logs
```

目录不存在时不要照抄命令；先按官方安装文档确认实际安装方式和路径。

**3. 使用项目提供的重启脚本**

```bash
cd ~/.claude/plugins/marketplaces/thedotmack
npm run worker:restart
```

该方式比结束所有 `node.exe`、`python.exe` 或使用 `Stop-Process -Force` 更可控。不要为释放一个端口终止不相关进程。

**4. 仍失败时保留证据**

保存插件版本、`worker:status`、脱敏日志和实际端口，再向项目官方 Issues/支持渠道反馈。日志中删除 Key、Token、提示词、用户名和私人路径。

---

## 预防措施

| 做法 | 目的 |
| --- | --- |
| 从官方 Release 更新并阅读变更说明 | 避免安装同名或过期版本 |
| 升级前备份 `~/.claude-mem/` | 保留本地记忆数据的恢复路径 |
| 使用 `worker:status`、`worker:logs`、`worker:restart` | 避免盲目杀进程或删除内部文件 |
| 只向官方项目提交脱敏日志 | 降低数据泄露风险 |
