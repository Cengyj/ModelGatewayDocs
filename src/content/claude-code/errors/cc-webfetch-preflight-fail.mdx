# CC-017：WebFetch 工具报错，目标网站可访问但仍失败

<ErrorMeta
  component="Claude Code 本体"
  version="v2.1.220 核对"
  platform="Linux / macOS / Windows"
  date="2026-07-26"
/>

---

## 问题现象

Claude Code 调用 WebFetch 时失败，但同一目标网页在浏览器中可以打开。浏览器可访问并不能证明 Claude Code 进程、代理、DNS、证书信任和目标站策略完全相同。

---

## 已撤下的未确认配置

旧版页面建议在 `settings.json` 中加入 `skipWebFetchPreflight: true`，并声称这是网络环境下的必做项。本次未能在 Anthropic 当前官方设置文档中确认该字段，因此不再提供或推荐。即使旧版本曾识别内部开关，也不能据此推定当前版本仍支持或安全。

---

## 排查步骤

1. 新开一个最小会话，记录 WebFetch 的完整错误、目标域名和发生时间
2. 检查 Claude Code 进程实际继承的 `HTTP_PROXY`、`HTTPS_PROXY` 与 `NO_PROXY`，确认符合组织网络策略
3. 检查系统时间、DNS、企业 TLS 代理证书和目标站是否拒绝自动化客户端
4. 暂时移除未在官方文档中出现的 `skip*` 或第三方注入字段，使用最小受支持配置复现
5. 升级到当前官方版本后重试，并通过 Anthropic 官方支持渠道提交可复现信息；提交前删除 Key、Token、Cookie 和私人 URL

<Callout type="warning">
不要通过跳过安全预检、关闭证书校验或伪造浏览器身份来强行抓取目标网站。目标站的访问控制、robots 规则和组织政策仍然适用。
</Callout>
