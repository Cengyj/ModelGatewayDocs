# CC-022：重复创建缓存导致单场重复收费

---

## 问题现象

个案中观察到疑似重复缓存计费。仅凭客户端等待时间或单张账单截图，无法确认是 Claude Code、模型提供方还是多层第三方转发造成。

---

## 根因分析

旧版页面把“备用负载切号、二次转发请求头”写成确定根因，并把首字时间超过 30 秒当成判断条件。本次没有从 Anthropic 官方文档或相关网关正式资料确认这条规则，因此将其标记为待网关核实，不再指导用户直接修改未知请求头。

---

## 修复步骤

1. 记录时间、模型、最终 Base URL、服务端请求 ID 和账单行；不要记录完整 Key 或提示词正文
2. 确认一次用户操作是否被客户端、重试逻辑或网关提交了多次
3. 若请求经过多层第三方转发，由网关运营方按请求 ID 核对路由、重试、缓存命中与计费记录
4. 在得到证据前不要删除未知请求头、轮换共享账号或继续进行高费用复现

---

## 预防措施

| 做法 | 避免的问题 |
| --- | --- |
| 保留服务端请求 ID 和账单明细 | 让提供方能够核对是否重复请求或重复计费 |
| 自动重试保持幂等并设置上限 | 避免客户端超时后重复提交 |
| 高费用复现前先获得网关支持确认 | 避免继续扩大未经确认的费用 |
