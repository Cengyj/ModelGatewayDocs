## 继续上次对话

```bash
# 接着上次中断的对话继续工作
claude --continue

# 查看所有后台会话，找到 session-id
claude agents

# 继续指定会话
claude --resume abc123
```

<Callout type="tip">`--continue` 是最常用的"回来继续干活"方式。Claude Code 会加载最近一次会话的上下文，你可以直接接着提问，不用重新交代背景。</Callout>

## 权限控制

Claude Code 会根据权限设置决定哪些工具需要确认。对不熟悉的仓库、外部提示或 CI 输入，保留默认确认和最小权限最安全。

### `--dangerously-skip-permissions`

```bash
claude --dangerously-skip-permissions
```

该参数会关闭工具确认，可能允许模型直接删除文件、执行外部命令或访问超出预期的资源。它不应作为日常推荐，也不应仅为减少提示而启用。

<Callout type="danger">只有在外部已经提供独立、可验证的隔离边界，并且任务输入、仓库内容和命令均已审查时，才考虑使用。默认做法是保留确认并使用细粒度权限规则。</Callout>

### 细粒度权限规则（推荐替代方案）

如果只想跳过特定工具的确认，在 `~/.claude/settings.json` 里用 `permissions.allow` 白名单更安全：

```json
{
  "permissions": {
    "allow": ["Bash(git status)", "Read(src/**)", "Write(src/**)"],
    "deny": ["Read(.env)", "Read(.env.*)", "Bash(git push --force:*)"]
  }
}
```

## 非交互模式（脚本场景）

```bash
# 一次性执行，结果输出到终端
claude --print "用中文总结一下这个 PR 的改动" 

# 输出 JSON（包含 token 用量）
claude --print --output-format json "列出 src/ 下所有函数名" 

# CI 中也应保留最小权限，并在隔离环境中运行
claude --print --output-format json \
  "检查 src/api.ts 里有没有 SQL 注入风险，输出报告"

# 把结果传给其他命令
claude --print "生成 .gitignore for Node.js 项目" > .gitignore.generated
```

先检查生成文件，再决定是否合并到现有 `.gitignore`，避免直接覆盖用户内容。

## 子代理 / 后台任务（v2.x）

```bash
# 查看所有正在运行的后台会话
claude agents

# 检查鉴权状态
claude auth status
claude auth status --text   # 人可读格式

```

认证命令和 Token 保存方式会影响账户安全；以当前 `claude auth --help` 和 Anthropic 官方文档为准，不在脚本或仓库中保存真实 Token。

## 版本与更新

```bash
# 查看版本
claude --version

# 更新到最新版（原生安装方式）
claude update
```

如需关闭后台自动更新，按官方文档在 `settings.json` 的 `env` 段设置 `"DISABLE_AUTOUPDATER": "1"`；手动 `claude update` 仍然可用。
