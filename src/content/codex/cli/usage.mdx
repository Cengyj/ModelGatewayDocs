## 审批与沙箱

<CommandTable header={['参数', '当前值']} rows={[
  { cmd: '--ask-for-approval, -a', desc: 'untrusted / on-request / never' },
  { cmd: '--sandbox, -s',          desc: 'read-only / workspace-write / danger-full-access' },
]} />

常用的受控组合：

```bash
# 只读分析；需要越界动作时再询问
codex --sandbox read-only --ask-for-approval on-request

# 允许写当前工作区，网络默认仍受限制
codex --sandbox workspace-write --ask-for-approval on-request
```

<Callout type="danger" title="不要把无审批等同于安全自动化">
`--ask-for-approval never` 只是不再询问，并不会自动增加安全边界。`danger-full-access` 或 `--dangerously-bypass-approvals-and-sandbox` 会移除关键保护，只能在外部已经独立加固和隔离的环境中考虑使用，不应作为教程默认值。
</Callout>

## 非交互模式

```bash
# 一次性执行
codex exec "用中文总结这个 PR 的改动"

# 指定只读沙箱
codex exec --sandbox read-only "检查 src/ 中潜在的注入风险，只输出报告"

# 指定模型（仅当当前登录或 provider 实际提供该模型）
codex exec --model gpt-5.6-sol "审查当前变更"
```

在 CI 中应把 API Key 限制在单次命令环境，避免写入仓库或全局日志。官方文档为非交互执行提供 `CODEX_API_KEY`；它只适用于 `codex exec`。

---

## 模型选择

OpenAI 当前 Codex 文档建议从默认 **Power** 设置开始，该设置使用 `gpt-5.6-sol` 与 medium reasoning；Sol、Terra、Luna 分别覆盖复杂高价值、日常通用和清晰重复任务。交互会话可用 `/model`，启动时可用 `--model` / `-m`。

<Callout type="warning" title="第三方网关模型另行核对">
OpenAI 官方推荐不代表 foropencode 或其他第三方网关已经提供同名模型。自定义 provider 下应以网关模型列表为准；不要手写未经网关确认的上下文或输出上限。`gpt-5.2` 与 `gpt-5.3-codex` 对 ChatGPT 登录的 Codex 已弃用。
</Callout>

## Profile 与项目配置

```bash
# ~/.codex/deep-review.config.toml
codex --profile deep-review
codex exec --profile deep-review "review this change"
```

Codex 0.134.0 及以后，Profile 文件为 `~/.codex/<profile-name>.config.toml`，通过 `--profile` 选择；不再使用旧 `CODEX_PROFILE=...` 或 `[profiles.<name>]` 方式。项目级 `.codex/config.toml` 只会在信任该项目时加载。

`AGENTS.md` 用于仓库级持久说明，离当前目录更近的文件对其子树生效。具体 slash 命令会随版本变化，请以会话中的 `/help` 为准。
