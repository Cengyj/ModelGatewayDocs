> Cherry Studio **只有桌面客户端**（Windows / macOS / Linux），没有 CLI 版本。

---

## 有什么能力？

| 功能 | 说明 |
| --- | --- |
| 多供应商支持 | 支持多种云端、本地和自定义 Provider；准确清单以当前客户端为准 |
| 300+ 助手模板 | 内置翻译、写作、代码审查等各类助手，可直接调用 |
| 本地知识库 | 拖入 PDF / Word / 网页，AI 基于本地文档回答 |
| MCP 支持 | 内置 MCP 协议，可调用文件系统、搜索、浏览器等工具 |
| 多模态 | 支持图片输入、图像生成（需对应模型） |
| 本地数据 | 对话历史、知识库索引和配置主要保存在本机；模型请求仍会发送到你选择的 API 提供商 |

## 安装

<Tabs defaultValue="win">
  <Tab label="Windows" value="win">
    从官方 Releases 下载后，打开 `.exe`，核对安装器显示的应用名称和发布信息，再按系统安装向导选择位置与选项。安装完成后从系统应用列表启动 Cherry Studio。
  </Tab>
  <Tab label="macOS" value="mac">
    1. 打开 `.dmg`，拖入 **Applications** 文件夹
    2. 首次启动若 Gatekeeper 提示发布方或签名无法验证，先停止打开，回到官方 Releases 核对下载来源，并查阅 Cherry Studio 官方支持说明；不要按教程绕过系统安全提示

    <Callout type="info">Apple Silicon 用户选择当前 Release 提供的 `arm64` 资产，Intel Mac 选择 `x64` 资产；文件名仍以发布页为准。</Callout>
  </Tab>
  <Tab label="Linux" value="linux">
    ```bash
    chmod +x Cherry-Studio-*.AppImage
    ./Cherry-Studio-*.AppImage
    ```

    如需集成到系统菜单，请优先查看 Cherry Studio Release 或发行版的 AppImage 说明；第三方 AppImage 管理器不是 Cherry Studio 官方安装所必需。
  </Tab>
</Tabs>

## 首次启动

<Steps>
  <Step title="打开 Cherry Studio">
    第一次启动会进入欢迎页。账户要求与可用功能取决于当前客户端版本和你选择的模型供应商；以应用内提示和官方文档为准。
  </Step>
  <Step title="选择主题与语言">
    左下角设置图标 → **常规设置** → 主题（亮 / 暗 / 跟随系统）+ 语言选「简体中文」。
  </Step>
  <Step title="进入「模型服务」准备配 API">
    左下角设置 → **模型服务**，从当前版本显示的 Provider 中选择对应服务。只在该 Provider 或自定义配置的正式界面填写 Key，并核对最终 API 域名。
  </Step>
</Steps>

## 常见问题

<Callout type="warning" title="启动报缺 GLIBC / OpenSSL（Linux）">
AppImage 仍可能依赖宿主系统库。若启动报错，先核对当前 Release 的资产说明和系统要求；不要根据旧页面固定升级到某个发行版版本。需要自行构建时只参考官方仓库当前的构建说明。
</Callout>

<Callout type="info" title="数据存哪？">
Cherry Studio 官方文档当前未逐项公布各平台数据目录。作为桌面（Electron 类）应用，其本地数据通常位于用户目录的应用数据文件夹（macOS 为 `~/Library/Application Support/`、Windows 为 `%APPDATA%`、Linux 为 `~/.config/` 下的对应子目录）；实际位置以应用内设置或官方文档当前说明为准。

这些目录通常包含对话历史、知识库索引、Provider 配置和助手模板。备份或迁移前先退出应用，并将其中的 API Key、Token 和账户信息按敏感数据处理。模型请求仍会发送到所选 API 提供商，不能把“本地存储”理解为“所有数据都不离开设备”。
</Callout>
