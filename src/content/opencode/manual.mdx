# OpenCode · 手动配置

<VersionBadge version="v1.17.8" date="2026-06-17" license="MIT" github="https://github.com/anomalyco/opencode" />

<PageHeader
  useCase="直接改 opencode.json 配 provider 与 model；项目级覆盖用户级"
  audience="一个供应商要接多模型；项目仓库要锁定模型/参数"
  tldr="provider 写 provider.<name>；model 字段格式 <name>/<model-id>"
/>

<Callout type="info">CLI 和桌面版 **共享同一份** `~/.config/opencode/opencode.json`。改一边两边都生效。</Callout>

---

## 配置文件位置

| 范围 | 路径 |
| --- | --- |
| 全局（推荐） | `~/.config/opencode/opencode.json` |
| 终端 UI 偏好 | `~/.config/opencode/tui.json` |
| 项目级（覆盖全局） | 仓库根目录 `opencode.json` |
| 缓存的鉴权信息 | `~/.local/share/opencode/auth.json` |
| 系统级（管理员部署） | macOS `/Library/Application Support/opencode/`、Linux `/etc/opencode/`、Windows `%ProgramData%\opencode` |

Windows 上 `~/.config/` 对应 `%APPDATA%`；`~/.local/share/` 对应 `%LOCALAPPDATA%`。

文件**格式是 JSONC**——可以写 `//` 注释。

---

## 最小可用模板

```json
{
  "provider": {
    "foropencode": {
      "options": {
        "baseURL": "https://foropencode.com/v1",
        "apiKey": "{env:OPENAI_API_KEY}"
      }
    }
  },
  "model": "foropencode/gpt-5.5"
}
```

然后导出 Key：

```bash
export OPENAI_API_KEY=sk-xxx
```

启动 `opencode`。

---

## 顶层字段

| 字段 | 含义 |
| --- | --- |
| `provider` | 所有供应商的字典 |
| `model` | 默认用哪个模型，格式 `<provider 名>/<model ID>` |
| `theme` | TUI 主题 |
| `keybinds` | 自定义快捷键 |
| `mcp` | MCP server 配置 |
| `agent` | 自定义 agent 行为（继承 `build` / `plan`） |
| `references` | 上下文引用文件列表（`reference` 已废弃，用 `references`） |

## `provider.<name>` 段

```json
{
  "provider": {
    "foropencode": {
      "options": {
        "baseURL": "https://foropencode.com/v1",
        "apiKey": "{env:OPENAI_API_KEY}"
      }
    },
    "anthropic-direct": {
      "options": {
        "baseURL": "https://foropencode.com",
        "apiKey": "{env:ANTHROPIC_API_KEY}"
      }
    }
  }
}
```

| 子字段 | 含义 |
| --- | --- |
| `options.baseURL` | API 根地址；OpenAI 兼容端点带 `/v1`，Anthropic 端点不带 |
| `options.apiKey` | API Key；可用 `{env:VAR}` 引用环境变量 |
| `options.headers` | 额外 HTTP 头，例如外接场景的 UA |
| `disabled` | `true` 时该 provider 不出现在选择器 |

`{env:VAR}` 和 `{file:PATH}` 是 OpenCode 的占位语法，启动时解析。这样 Key 不进配置文件，安全些。

<Callout type="tip" title="自定义 provider 要不要写 npm 字段？">
OpenCode 基于 AI SDK 选适配器。如果你的 provider ID **复用内置名**（如 `anthropic`、`openai`），只填 `options.baseURL` 覆盖即可。但如果是**全新的自定义 ID**（如本站 `foropencode`），OpenAI 兼容端点建议显式加 `"npm": "@ai-sdk/openai-compatible"`，Anthropic 端点用 `"npm": "@ai-sdk/anthropic"`，OpenCode 才知道该用哪个适配器去请求。

来源：[OpenCode Providers 官方文档](https://opencode.ai/docs/providers/)（2026-06 核对）
</Callout>

| 字段 | 含义 |
| --- | --- |
| `options.contextLength` | 上下文窗口 Token 数 |
| `options.maxTokens` | 单次最大输出 Token 数 |
| `variants` | 推理深度档位；每个 key 是档位名，值为 `{ "reasoningEffort": "low\|medium\|high" }` |
| `modalities.input` | 模型接受的输入类型，可填 `text`、`image`、`audio`、`video`、`pdf` |
| `modalities.output` | 模型可输出的类型，可填 `text`、`image`、`audio` |

以上字段均可省略——省略时 OpenCode 自动推断，但显式声明可让选择器正确显示档位和附件支持。

<Callout type="warning">**gpt-5.5 普通渠道有效上下文约 270K**——超出后遇到 `context_length_exceeded` 时开新会话即可；Pro/Plus Codex 账号可将 `contextLength` 改为 `1050000`。</Callout>

## 多 provider + model 前缀

```json
{
  "provider": {
    "fc-claude": {
      "options": {
        "baseURL": "https://foropencode.com",
        "apiKey": "{env:ANTHROPIC_KEY}"
      }
    },
    "fc-gpt": {
      "options": {
        "baseURL": "https://foropencode.com/v1",
        "apiKey": "{env:OPENAI_KEY}"
      }
    }
  },
  "model": "fc-gpt/gpt-5.5"
}
```

`model` 字段的前缀必须对应 `provider` 里某个 ID。切换模型时改前缀即可：

```json
{ "model": "fc-claude/claude-sonnet-4-6" }
```

## 项目级覆盖

仓库根放一个 `opencode.json`：

```json
{
  "model": "fc-claude/claude-haiku-4-5"
}
```

启动 `opencode` 时项目级会**合并**到全局上，**项目级优先**。

适用场景：

- 团队仓库锁定模型（避免大家随便切）
- 不同项目用不同 Key（项目级覆盖 `provider.<name>.options.apiKey`）
- CI 里跑 OpenCode，项目里直接写好

---

## 环境变量覆盖

| 变量 | 作用 |
| --- | --- |
| `OPENCODE_CONFIG` | 指定单个配置文件路径 |
| `OPENCODE_CONFIG_DIR` | 指定配置目录 |
| `OPENCODE_CONFIG_CONTENT` | 直接把 JSON 内容塞进环境变量 |
| `OPENCODE_TUI_CONFIG` | 终端 UI 配置 |
| `OPENCODE_MODEL` | 本次会话用的模型，覆盖配置文件 |

```bash
OPENCODE_MODEL="fc-claude/claude-opus-4-7" opencode
```

## CLI vs 桌面版 的差异

| 维度 | CLI | 桌面版 |
| --- | --- | --- |
| 配置文件 | `~/.config/opencode/opencode.json` | **同一个** |
| 项目级覆盖 | 自动读 cwd 下的 `opencode.json` | 同 |
| 当前稳定度 | 主线稳定 | BETA |
| 完全独立配置 | 用 `OPENCODE_CONFIG_DIR` 指向另一个目录 | 给桌面版单独建启动脚本传 env |

改完 config：

- CLI：重启 `opencode`
- 桌面版：完全退出 + 重启

## 常见排查

| 现象 | 检查 |
| --- | --- |
| 启动报 `model not found` | `model` 前缀是不是 `provider` 里某个 ID |
| `apiKey is empty` | `{env:VAR}` 引用的环境变量是否真的有值 |
| 桌面版读不到 config | 完全退出（含菜单栏图标）再启动；BETA 期偶有缓存问题 |
| `reference is deprecated` | 把 `reference` 改成 `references`（v1.17.0+ breaking change） |
